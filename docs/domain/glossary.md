# Słownik pojęć domenowych

Polskie definicje i angielskie nazwy tworzą jeden słownik, nie tłumaczenie wymagań. Właściciel reguły pozostaje w przywołanym Issue; słownik jest odniesieniem pochodnym. Nazwy są tożsamościami pojęć, **nie nakazem tworzenia nowych tabel, kolekcji, pól ani schematów**. Istniejące wymagania modelu w Issue zachowują swój zakres.

Czytaj także [indeks](../index.md), [przykłady](../reference-examples.md), [otwarte decyzje](../decisions.md) i [opis Workforce Planning](../workforce-planning.md).

| Termin polski / English identity | Znaczenie i granica | Właściciel kontraktu i źródło |
|---|---|---|
| Plan produkcji / `ProductionPlan` | Zapisane pozycje ilości i terminów gotowości, powiązane z opublikowanymi wersjami receptur. Nie jest wynikiem kalkulatora #17, grafikiem osób ani wykonaniem partii. | [#33](https://github.com/slawinski/5ciastek/issues/33), definicje, REQ-01–REQ-04, AC-01 |
| Zatwierdzona wersja planu / approved `ProductionPlan` version | Konkretna wersja udostępniana odbiorcom z identyfikatorem i wersją. Nowy szkic nie zastępuje jej przed zatwierdzeniem następcy. Zatwierdzenie ilości nie potwierdza wykonalności zasobów ani nie tworzy rzeczywistej partii. | [#33](https://github.com/slawinski/5ciastek/issues/33), REQ-02–REQ-04, AC-02–AC-04 |
| Grafik zmiany / `ShiftPlan` | Planowane godziny i przerwy konkretnej osoby, z własną publikacją i historią. Nie jest planem ilości produkcji ani dowodem obecności. Jeden model dla 1–N osób; szacunek wsteczny nie gwarantuje wykonalności. | [#27](https://github.com/slawinski/5ciastek/issues/27), REQ-01–REQ-08, AC-01–AC-07; [#29](https://github.com/slawinski/5ciastek/issues/29), granica publikacji |
| Indywidualny zapis pracy/obecności / `WorkSession` | Rzeczywiste godziny osoby, przerwy i kontrolowane korekty. Obecność, płatna praca i formalna ewidencja nie są synonimami. Domyślnie dane operacyjne/eksport; formalne użycie wymaga osobnej weryfikacji. | [#28](https://github.com/slawinski/5ciastek/issues/28), REQ-01–REQ-06, AC-01–AC-06 |
| Partia ciasta / `ProductionBatch` | Osobny zapis wykonania związany z niezmienną opublikowaną wersją receptury i planowaną masą/liczbą sztuk. Sam plan ani animacja nie dowodzą wykonania. | [#18](https://github.com/slawinski/5ciastek/issues/18), definicje, REQ-01, AC-08; [#33](https://github.com/slawinski/5ciastek/issues/33), REQ-04 |
| Etap / `phase` | Okres technologiczny, np. fermentacja. Może zawierać krótkie operacje aktywne; czas pasywny nie jest ciągłą pracą ludzi. | [#18](https://github.com/slawinski/5ciastek/issues/18), definicje, REQ-05/REQ-13, AC-01/AC-03 |
| Operacja / `task` | Konkretna czynność, np. składanie lub formowanie. Może trwać wewnątrz etapu bez jego zakończenia. Czas operacji i nakład osobominut to różne wyniki. | [#18](https://github.com/slawinski/5ciastek/issues/18), AC-03–AC-05 |
| Odcinek nakładu pracy / `LaborSegment` | Okres obowiązywania liczby osób na operacji; nakład = czas × `workerCount`. Zmiana obsady tworzy kolejny odcinek; odcinki jednej operacji nie nakładają się. Anonimowe deklaracje nie identyfikują unikalnych osób ani nie zastępują `WorkSession`. Współdzielenie wymaga jawnej alokacji do dokładnych kosztów. | [#18](https://github.com/slawinski/5ciastek/issues/18), AC-04/AC-05/AC-LAB-01; [#34](https://github.com/slawinski/5ciastek/issues/34), REQ-02; [#5](https://github.com/slawinski/5ciastek/issues/5), AC-LAB-01; [#43](https://github.com/slawinski/5ciastek/issues/43), AC-01/AC-02 |
| Wersja receptury / `recipeVersion` | Opublikowana wersja pełnej samodzielnej receptury, z masami i dodatnim całkowitym uzyskiem. Masa porcji jest pochodną sumy mas / uzysk, nie drugim niezależnym źródłem. Odnośnik do bazy nie dodaje składników. | [#14](https://github.com/slawinski/5ciastek/issues/14), REQ-03–REQ-05/REQ-08–REQ-10, AC-YIELD-01/AC-VAR-01 |
| Historyczna kompozycja składników / historical ingredient composition | Zamrożone w opublikowanej wersji wartości klasyfikacji, mąki/wody zakwasu, typów mąki i mas. Stabilna relacja do surowca nie uprawnia do przeliczenia historii z jego bieżącej klasyfikacji. Brak składu zakwasu nie daje dokładnych procentów. | [#14](https://github.com/slawinski/5ciastek/issues/14), AC-09/AC-HIST-01; [#17](https://github.com/slawinski/5ciastek/issues/17), AC-07/AC-10/AC-HIST-01 |
| Identyfikator produktu sprzedażowego / `SKU` | Stabilna tożsamość produktu do przypięcia sprzedaży i bilansu; nie identyfikator partii ani wersji receptury. Plan wskazuje SKU, gdy mapowanie istnieje; brak mapowania blokuje eksport wymagający SKU. | [#4](https://github.com/slawinski/5ciastek/issues/4), zadania i AC-BAL-01–AC-BAL-03; [#33](https://github.com/slawinski/5ciastek/issues/33), dane wejściowe |
| Stan fizyczny / physical stock | Ilość fizycznie przyjęta i pozostająca w danej lokalizacji, okresie i jednostce. Potwierdzony zwrot niesprzedawalny zwiększa ten stan; sam refund nie. | [#4](https://github.com/slawinski/5ciastek/issues/4), AC-BAL-01–AC-BAL-03 |
| Stan dostępny do sprzedaży / saleable stock | Część stanu dopuszczona do sprzedaży według procedury zakładu. Fizyczny zwrot nie oznacza automatycznego dopuszczenia; nie wolno drugi raz odejmować tego samego odpadu/zwrotu. | [#4](https://github.com/slawinski/5ciastek/issues/4), AC-BAL-02/AC-BAL-03 |
| Zdarzenie / `ActivityEvent` | Wersjonowany zapis faktu z tożsamością, czasem zajścia i zapisu, źródłem oraz kolejnością w strumieniu; zapis rzeczywisty ma autora. `manual` i izolowane `simulation` mają tę samą semantykę, nie wspólny rejestr produkcyjny. Start/stop nie dowodzi transferu ani zajęcia urządzenia. | [#18](https://github.com/slawinski/5ciastek/issues/18), wspólny kontrakt, AC-CONTRACT-01/AC-CONTRACT-02; [#30](https://github.com/slawinski/5ciastek/issues/30), AC-06/AC-CONTRACT-01 |
| Projekcja / projection | Odtwarzalny stan wyprowadzony z zatwierdzonych zdarzeń, wspólny dla źródeł ręcznych i symulowanych. Nie jest drugim ręcznie utrzymywanym modelem prawdy ani dowodem ruchu z animacji. Korekta wymaga spójnego przeliczenia zależności lub odrzucenia. | [#18](https://github.com/slawinski/5ciastek/issues/18), AC-CONTRACT-01; [#34](https://github.com/slawinski/5ciastek/issues/34), REQ-03; [#37](https://github.com/slawinski/5ciastek/issues/37), REQ-01/REQ-03, AC-01–AC-03 |
| Planowane obciążenie/rezerwacja zasobu / planned resource occupation | Zamiar harmonogramu CAPP, nie fakt pracy maszyny. Osobne wejście planistyczne; brak potwierdzenia wykonania pozostaje brakiem danych. | [#18](https://github.com/slawinski/5ciastek/issues/18), kontrakt i AC-CONTRACT-02; [#36](https://github.com/slawinski/5ciastek/issues/36), REQ-03, AC-03 |
| Rzeczywiste zajęcie zasobu / actual resource occupation | Potwierdzone przypisanie i zwolnienie konkretnego zasobu. `resource_reserved` w kontrakcie #18 oznacza właśnie zajęcie wykonawcze, nie plan. Znana pojemność podlega walidacji we wspólnej jednostce; nieznana nie oznacza bezpiecznej dostępności. | [#36](https://github.com/slawinski/5ciastek/issues/36), REQ-01–REQ-03, AC-01–AC-03; [#18](https://github.com/slawinski/5ciastek/issues/18), typy kontraktu |
| Aktualność źródła / source freshness | Potwierdzenie, że źródło odpowiada, oceniane oddzielnie od ostatniego zdarzenia według jawnego interwału/progu adaptera. Błąd odczytu oznaczyć od razu; historyczny snapshot nie udaje bieżącego. | [#42](https://github.com/slawinski/5ciastek/issues/42), REQ-01–REQ-03, AC-01–AC-03 |
| Wiek zdarzenia / event age | Czas od ostatniego faktu produkcyjnego. Cztery godziny cichej fermentacji nie oznaczają awarii, jeżeli odczyty źródła są poprawne; pauza zegara demo nie jest awarią live. | [#42](https://github.com/slawinski/5ciastek/issues/42), AC-01/AC-03 |

## Granice interpretacji

Tożsamości osób i ich czas podlegają rolom, minimalizacji i retencji z [engineering assurance](../engineering-assurance.md), #21/#23 i #28. Historia techniczna nie ustanawia bezterminowej retencji danych osobowych. Nie identyfikować ani nie oceniać pracowników kamerami bez odrębnej oceny prawa i prywatności. Słownik nie potwierdza zgodności prawnej ani wdrożenia funkcji.
