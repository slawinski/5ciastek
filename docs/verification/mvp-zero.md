#### Durability causal chain and fix

1. The original post-contention regression was restored **before** the new draft/bulk writes. It failed: a fulfilled create was absent from an independent SQLite connection immediately after resolution.
2. The defect reproduces without application hooks using installed `@libsql/client` **0.14.0** / native `libsql` **0.4.7**: first writer starts, competing BEGIN fails SQLITE_BUSY, first writer commits, then a later transaction accepts an insert but COMMIT fails with `cannot commit transaction - SQL statements in progress`.
3. Installed `@libsql/client/lib-esm/sqlite3.js:123–127` retains its cached connection when BEGIN throws (the detach occurs only after success). Its prepared-statement execution at lines 247–277 does not finalize a failed statement. In installed `@payloadcms/drizzle/dist/transactions/beginTransaction.js:20–43`, the catch notifies the already-settled readiness promise even for a later COMMIT failure, consuming the transaction rejection. Consequently `commitTransaction.js:11–15` sees a resolved completion and the Payload API can return a successful but rolled-back write.
4. Two intermediate candidates were rejected rather than shipped: a separate client around Drizzle's transaction callback fixed the initial sequence but did not dispose its detached failed-commit connection; direct prepared COMMIT still left the forced-commit-failure regression blocking subsequent commits. Reconnecting the ordinary read client did not fix that lock. These experiments and temporary logging were removed.
5. `src/db/sqlite.ts` now owns an attached local client per transaction, uses BEGIN IMMEDIATE, registers its Drizzle view in Payload's normal request session registry, and closes it on failed begin, rollback or commit. Finalization uses the pinned local driver's **executeMultiple** path (native exec, not prepared COMMIT), whose finally rolls back a failed transaction. Commit rejection propagates to the API instead of being swallowed. Normal Payload request transaction propagation and publication ACLs are unchanged; single writes have no hidden retry or false success. Native bulk publication had a separate operation-level rollback/reporting defect, closed by the later server guard below, not by this adapter. The wrapper refuses remote/non-file clients because this guarantee relies on the installed local driver's connection semantics. Existing transitive driver/Drizzle versions were promoted to pinned direct dependencies, without changing their versions.

The migrated integration fixture now forces an **actual COMMIT failure** using a second connection's read lock: the publication rejects and neither its counter nor snapshot changes. It then performs **three contention rounds**, requiring a committed winner and rejected loser each time. Subsequent distinct draft writes must already be visible from an independent connection; bulk publication must reject without writes; individual publication of those drafts must have distinct snapshots and counters; another sequential publication must have the next counter and complete contiguous independently persisted history. After closing/copying the DB and the migration-failure drill, a separate Payload process reads the post-contention publication/counter and both exact draft snapshots back. No test ordering workaround or manual reconnect remains. Production HTTP smoke also performs concurrent publications before fresh writes, verifies bulk rejection and individual publication, and reads committed history through an independent SQLite connection.

### Final focused-review corrections — 2026-11-25

- **Nested bulk failure / false success (P1):** A new failing regression let the first publication finish, then threw from the second publication's afterChange hook. Native bulk update returned one success document at counter 1 and one error, but independent readback showed both counters 0 and no publications. A nested create failure calls Payload's killTransaction, rolling back the shared transaction and deleting req.transactionID; native bulk catches the per-document error and retains earlier success documents, then has no live transaction left to commit. The adapter's correct single-transaction behavior cannot repair that result contract. Since requirements only require individual publication, a collection beforeOperation guard now rejects publishing without an ID before document processing, including override-access Local API and where queries matching one row. The generic draft bulk path remains supported. REST returns clear 400 errors for boolean/string true and leaves names, timestamps, counters and publications unchanged. Supported individual create/update publication still works. The production smoke against the previous build first failed with 200 instead of the expected rejection.
- **Migration URI/backup bypass (P1):** The previous resolve(target.slice(5)) checked percent-encoded/authority/query text as a different filesystem path from the driver's actual file. In an owned fixture cwd with a fake Payload child, encoded-dot, localhost, query, fragment and remote-authority variants all reached the child with no backup. The guard now uses fileURLToPath, rejects unsupported authority/query/fragment/null-byte forms and passes only the canonical pathToFileURL target to the child. Encoded local paths and localhost normalize to the actual target, require its backup and reject that same file as backup. Tests verify canonical child DATABASE_URI/CONFIRM_DATABASE_URI with a separate backup, and unchanged source bytes. No unknown or actual production file was used.
- **Migration failure proof (P2):** Matching a migration name from the runner's pre-execution log did not prove CREATE ran. The fixture now emits `INJECTED_MIGRATION_DDL_APPLIED` only after awaited successful CREATE. The test requires that exact stdout line, the intended `INSERT INTO missing_table` query/error, nonzero exit, no partial table/history entry, preserved snapshot/FKs and an untouched source. The stronger assertion first failed on the old fixture's missing marker. This prevents an early CREATE failure from passing as a rollback drill.

The dedicated-client transaction adapter was not redesigned in this correction. Parent shipping/browser/CI and real-data approvals remain separate; no commit/push or ideation edits were made.
